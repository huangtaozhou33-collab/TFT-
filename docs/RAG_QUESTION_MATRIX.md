# 玩家问题与 RAG 验收矩阵

本文件把玩家可能提出的问题映射到所需数据、查询路径和缺失行为。它是产品与工程验收清单，不表示表中每项已经实现。架构与阶段见 [RAG_ARCHITECTURE.md](RAG_ARCHITECTURE.md)。

## 1. 使用原则

- 数值、规则、选手意见、模型分析分别标明证据类型。
- 当前统计读取来源明确属于当前补丁的记录，或经用户批准策略推定归档到当前补丁的 OP.GG 记录；推定必须可见且可追溯。明确其他补丁、未知且无有效归档的记录仍拒绝，历史记录仅供明确历史查询或维护检查。
- 不知道、不支持、未采集、同步失败和真实零样本必须区分。
- 玩家用昵称、省略主语和连续追问是正常输入，不能要求每次重写完整条件。
- 统计排序结果不是因果结论，更不是单局收益保证。
- 表中“应答”说明行为，不填写未验证的游戏数值。

## 2. 统计查询

| ID | 玩家问题 | 查询路径与所需数据 | 应答与失败行为 | 验收关键点 |
| --- | --- | --- | --- | --- |
| S01 | 小法什么装备表现最好？ | 解析昵称 → 英雄出装统计；版本、指标、样本量 | 返回真实组合／指标和当前筛选口径；“最好”的排序依据可见 | 不能从单件排名拼三件套；缺补丁仅在有效归档下可答，并标明推定 |
| S02 | 小法有黎明核心，剩下两件怎么出？ | 英雄＋固定装备 → 完整装备组合条件查询 | 返回真实包含该装备的组合；不支持就说明来源能力缺失 | 每个返回组合确含装备，保留重复装备数量 |
| S03 | 我锁定这三个棋子，小法带什么？ | 全部英雄条件和目标英雄交给同一个统计服务 | 只用符合全部条件的真实观测；没有联合源时返回不支持 | 禁止用三个英雄的边际统计做连接；不先要求选择命名阵容 |
| S04 | 这个神器给谁？ | 装备 ID → 携带者统计 | 列英雄、指标与样本量 | 不能用技能文字推演代替统计推荐 |
| S05 | 这两个三件套哪个好？ | 同一补丁、模式、段位、地区和条件下比较 | 指标并排显示，样本差异可见；口径不同时拒绝直接比较 | 不把两个来源的未知口径拼成确定比较 |
| S06 | 只看大师以上呢？ | 修改当前查询的段位字段，检查来源能力 | 支持才执行；否则说明来源未提供该维度 | 不把 UI 下拉值当成数据真的已被过滤 |
| S07 | 按前四率排，别按吃鸡率 | 修改排序后重新查询或对同一有效结果排序 | 条件保持不变，排序字段可见 | 模型不能修改或补写指标 |
| S08 | 为什么第一名只有十几场？ | 读取真实样本数与样本单位 | 保留结果并提示不稳定性，不自动剔除或补样本 | 低样本是提示，不等于没有结果 |
| S09 | 为什么搜这个装备没结果？ | 读取能力、采集批次、补丁和匹配状态 | 明确是哪一类缺失，真实零匹配才说零样本 | 覆盖“不支持／未采集／补丁未知／失败／真实空” |
| S10 | 这个版本刚更新，最强装备是什么？ | 校验活跃游戏补丁与统计数据集补丁 | 新补丁未就绪就说明；不展示旧版作为当前 | 缓存命中也必须遵守版本隔离 |
| S11 | 我有这个转职，能看装备、队友、阵容吗？ | 转职是装备实体，条件传入统一研究查询 | 三栏采用相同条件；每栏说明自己的实际证据和样本单位 | 来源阵容方案数不能改名为对局样本数 |
| S12 | 我已经有两把这个装备 | 带重复次数的装备条件 | 来源支持才执行数量约束 | 去重算法不能抹掉装备数量条件 |

当前 OP.GG 聚合缓存和少量来源阵容不足以兑现所有 S 类问题。数据库建设能准确表达能力缺口，但不能替代真实联合统计数据源。本轮 201 份缺补丁可用快照已按受审策略推定归档，原始 `sourcePatch:null` 保留；另 1 份 `not_supported` 仍不提供结果。日历或来源页面不能证明统计窗口的全部样本仅属于当前主补丁，也不能确认 B 更新范围。能力与证据见 [OPGG_DATA_CONTRACT.md](OPGG_DATA_CONTRACT.md)。

后续实际交付：Riot 玩家终局表与共用查询已接通，S03 的“三棋子同一玩家＋指定持有者装备”经过真实原始记录与 MySQL 比对；复制棋子、重复装备、旧补丁和空结果边界通过真实 SQL 验收。当前有 36 场、288 份合格终局，低样本仅提示，不能据此声明所有 S 类维度已支持。方法与局限见 [RIOT_PIPELINE.md](RIOT_PIPELINE.md)。

## 3. 赛季规则、奖励与实体速查

| ID | 玩家问题 | 查询路径与所需数据 | 应答与失败行为 | 切片／字段要求 |
| --- | --- | --- | --- | --- |
| K01 | 这个法杖什么时候出现？ | 别名 → 实体 → 已核验出现规则 | 阶段、模式、前提、冷却和互斥，附来源与版本 | 整体保留条件；区分出现、购买和效果触发 |
| K02 | 我为什么刷不到它？ | K01 规则＋玩家提供的相关状态 | 对确定不满足的条件解释；必要输入未知时只追问缺项 | 支持 all／any、未知状态；没刷到不证明条件不满足 |
| K03 | 这个海克斯能开出什么？ | 实体关联奖励表 → 对应档位 | 奖励图片、数量、概率和触发条件 | 同一条件所有分支、概率分母、脚注不可拆散 |
| K04 | 六个羁绊这一档有什么？ | 解析档位 → 精确条件组 | 只返回符合档位的完整分支；版本冲突则不给当前数值断言 | 不只取最高相似的一行；不截掉第二个分支 |
| K05 | 蓝色／金色球里会有什么？ | 法球别名与图标 → 阶段掉落池 | 展示图片帮助确认，再返回适用掉落规则 | 同色不同阶段不能混为一条无条件规则 |
| K06 | 这个羁绊的属性怎么算？ | 精确规则、公式和输入 | 给已核验公式及例子；输入不足不填默认事实 | 输入变量、单位、上限和例外作为完整组 |
| K07 | 这个海克斯和法杖冲突吗？ | 实体关系／互斥条件 | 区分明确互斥、明确兼容、未找到记载 | “没有关系记录”不能映射为兼容 |
| K08 | 八级刷四费概率是多少？ | 系统概率表的等级行 | 返回当前已核验表值及表格入口 | 表头、等级、单位随行保留；不是英雄胜率 |
| K09 | 下一次刷新出指定四费的概率呢？ | 识别为更具体概率问题，检查卡池等输入 | 不拿商店四费概率直接充当指定英雄概率 | 记录计算所需变量，缺失即说明 |
| K10 | 这个转职怎么合？ | 实体关系中的合成记录 | 返回两个材料图标或明确不可合成 | “未收录配方”与“确定不可合成”分开 |
| K11 | 普通版和光明版差在哪？ | 关联实体的同版本属性 | 并排列已核验差异 | 不用名称相似度自动认定是同一系列 |
| K12 | 这个英雄是什么费用、什么羁绊？ | 图鉴实体查询 | 名称、费用、羁绊、技能及图标 | 形态与升级变体不能覆盖基础实体 |
| K13 | 上个版本这个法杖改了什么？ | 显式历史意图 → 两个版本记录／变更证据 | 展示变更前后及各自来源；没有旧记录就说明 | 历史查询不能改动当前统计上下文 |
| K14 | 资料里没有这个新机制，你帮我查一下 | 本地缺失 → 后续联网工具 | 查询指定来源，标记联网／未入库／未核验 | 联网返回不能直接标记 reviewed；本轮尚未接通则如实说明 |

## 4. 连续追问与歧义

| ID | 对话序列 | 期望状态变化 | 验收关键点 |
| --- | --- | --- | --- |
| C01 | 小法带什么 → 已经有黎明核心了 | 解析实体后添加绑定小法的装备条件 | 第二问继承英雄，来源能力不足不退回无条件榜 |
| C02 | 再加这两个队友 | 在原状态中追加英雄条件 | 与原装备条件同时成立，不覆盖原有条件 |
| C03 | 那只看前四率 | 只修改排序 | 版本、段位、目标与条件保持 |
| C04 | 把黎明核心去掉 | 删除精确装备条件 | 不清空全部筛选，返回当前条件摘要 |
| C05 | 换另一个英雄看看 | 目标不明确则澄清，明确则修改目标 | 不凭猜测删除队友条件；查询目标与队伍条件分开 |
| C06 | 同一个昵称可能指两个实体 | 保留候选并询问确认 | 不使用向量分数强行消除真实歧义 |
| C07 | 前端改了条件，再打开助手问这个呢 | 从经过服务端校验的前端状态接续 | 浏览器传来的统计数值不是可信事实 |
| C08 | 旧对话持续到新补丁发布 | 重新确认有效版本，发起当前查询 | Redis 会话中的旧 patch 不能绕过硬隔离 |

建议以结构化状态及显式操作实现，完整对话状态接入属于后续阶段。已有聊天记录保存或前端 URL 保存不等于这些语义都已实现。

## 7. 最低自动化与人工验收

以下用例应优先变为确定性测试；检索质量与模型解释另设评测，不能只测试一条成功回答。

1. **版本与推定边界**：同时放来源当前、来源历史、缺补丁无归档、缺补丁有受审当前归档的同名统计。仅前者和最后一类可返回；推定保留来源空值及提示，明确错误来源版本不能被归档覆盖。改变快照内容哈希、发布或超出原采集窗口，归档不能继续生效；重复执行不新增变更。
2. **冲突隔离**：文档名称完全命中但 `eligible=false`；不得进入当前数值证据。
3. **奖励完整性**：命中一个条件档位；返回该组全部分支、表头和脚注。
4. **组合真实性**：固定一件装备；结果每组都真实含它，不由单件统计拼装。
5. **联合能力缺失**：数据源只支持单英雄；追加第二个英雄返回不支持，不退回单英雄答案。
6. **样本语义**：匹配两个来源阵容方案；不能返回“样本量为两局”。
7. **重复导入**：同一个版本包导入两次；实体、片段和发布记录不重复，原采集时间不变。
8. **无 embedding**：不配置模型；检索可以使用词法，状态明确为 lexical，向量分数为空。
9. **过期向量**：Milvus 返回已撤回或不同哈希片段；MySQL 二次检查将其排除。
10. **索引覆盖不足**：只完成部分索引；不能自称完整 hybrid 检索，明确降级或等待发布。
11. **缓存失效**：发布切换后，同一句问题不能命中上一发布的答案缓存。
12. **Redis 故障**：数据库正常；查询仍可返回，记录缓存降级，不伪报资料缺失。
13. **连续追问**：添加英雄、追加装备、修改排序、删除装备；每步状态变更可检查且没有隐式放宽。
14. **统计和规则分离**：询问掉落概率；不得用英雄胜率作为证据，反之亦然。
15. **图标证据**：奖励／法球结果具有正确图片引用；缺图状态明确，不显示不相关图片。

检索评测应记录：问题 ID、预期实体、预期证据 ID、适用补丁、禁止出现的证据、检索模式、召回排名、最终引用、必要事实是否完整。证据召回率与最终回答正确率分开统计；阈值和 top-K 用这些结果调优，不能用单一向量相似度代替事实核验。

完成记录必须区分单元测试、使用 mock 的集成测试、实际数据库／Milvus 联通、真实模型 API 与人工浏览器验证。尚未执行的项保持待验收，不因为设计文档有对应行就打勾。
