# TFT Atelier · 中文机制资料库 V4

> **状态：V4 本机研究版 / beta。** 支持图鉴、统计筛选、工具调用问答与知识检索；不等于公网生产服务。最新发布边界见 [发布检查](../../docs/RELEASE_READINESS.md)，完整文件导航见 [项目指南](../../docs/PROJECT_GUIDE.md)。下文早期版本数量为历史记录。

## 新用户快速开始

Windows：安装并启动 Docker Desktop（Linux引擎），在克隆后的项目目录运行：

```powershell
.\start-docker.cmd -Rag
```

打开 http://127.0.0.1:3001 。首启会生成自己的配置与数据库密码。聊天Key、Embedding和向量索引需自行配置；没有Key仍可浏览资料。
macOS/Linux统一命令见 [跨平台启动](../../docs/PROJECT_GUIDE.md#跨平台-docker-启动)。

**数据边界：** Git不会包含开发者本机MySQL、Redis、Milvus卷或私人笔记。种子包是历史资料与统计，新用户需要在开发者模式同步MetaTFT；数据源失效或不可访问时无法保证与你在演示中看到的覆盖一致。

开发验证（Node.js 22+）：`npm ci` 后 `npm test`，测试夹具自动准备，无需模型Key。历史采集与真实提供商验收不放进普通CI。代码许可证尚未选定，第三方数据与图片分发许可另行确认。


中文、本机运行的 PC TFT 研究工具。左侧导航提供阵容首页、阵容规划器、大数据、筛选器、资料库和开发者模式，右下角提供 TFT 助手。数据库部署版的三个统计入口和 Agent 目前共用 MetaTFT/MySQL；Milvus 负责机制和术语检索，Redis 缓存知识查询及不可变统计快照行。旧 OP.GG/Tactics.tools 发布包和 Riot 对局独立留存，不与 MetaTFT 合并样本。

开发者模式新增「统计自动更新」：五类统计任务默认每天检查，可各自设置 1～168 小时、暂停或立即运行；MySQL 保存配置与任务历史，资料库仍按赛季发布。实际采集路径、数据边界和恢复说明见 [统计调度](../../docs/STATISTICS_SCHEDULE.md)。

2026-10-11 已增加光明出装开关、基础散件分类，以及 10 个单独段位和“铂金及以上 / 全部段位”的查询。74 个棋子/形态、137 件装备均纳入批量采集目标；2,556 个任务中 2,555 个已入库核验，全部段位苍蓝雕纹魔像出装仍因来源 HTTP 500 缺失。来源候选有截断，不能称作全部可能组合。当前架构、精确数量、已修复项、剩余限制与维护命令见 [V4 数据架构](../../docs/DATABASE_ARCHITECTURE.md)。下方 V1–V3 交付和较早数量保留为历史记录，以该架构文档和实时审计为准。

V4 第一阶段已接入用户提供的 184 条中文社区术语，保留 7 条未被覆盖的原有概念，共 191 条。词库用于理解问题、召回解释与保留多义词候选；历史装备、英雄昵称和赛季机制不代表当前赛季可用。证据标签与参考链接按用户材料保留，本次未逐条独立复核。数据格式、匹配边界和验收见 [V4 术语说明](../../docs/V4_GLOSSARY.md)。

## 运行

推荐使用 Docker 启动数据库版；原本地 JSON 开发入口继续保留，两者默认端口不同。

| 入口 | 地址 | 数据行为 |
| --- | --- | --- |
| `start-docker.ps1` | `http://127.0.0.1:3001` | 应用、MySQL、Redis；首启导入种子包并应用已核对的补丁归档规则，隔离无归属或不同补丁统计 |
| `start-docker.ps1 -Rag` | `http://127.0.0.1:3001` | 以上服务加 Milvus、etcd、MinIO；配置 embedding 并建索引后才启用向量检索 |
| `start.cmd` / `npm start` | `http://127.0.0.1:3000` | 默认原 `local_json` 开发模式，保留来源缓存用于开发对照 |

Docker Desktop 使用 Linux / WSL2 引擎时，在项目目录执行：

```powershell
.\start-docker.ps1 -Rag
```

首次启动生成独立的 `.env.docker` 和随机数据库密码，不读取或覆盖开发用 `.env`。模型 Key 默认留空；无需模型即可浏览资料库、可用统计和阵容规划器，AI 问答需要配置聊天 API，向量检索另需配置 embedding API。完整步骤见 [Docker 与 RAG 配置](../../docs/RAG_SETUP.md)。

本地开发需要 Node.js 22 或更新版本，先执行 `npm ci` 安装锁定依赖；当前使用 `mysql2` 与 `redis` 客户端。

1. AI 问答使用 `.env` 中的 `AI_API_KEY`、`AI_BASE_URL` 和 `AI_MODEL`；选择自己可用的兼容服务。没有 Key 不影响普通资料浏览。
2. 在此目录执行 `npm start`，或双击 `start.cmd`。
3. 打开 <http://127.0.0.1:3000>。如果端口被占用，修改 `.env` 的 `PORT`。

本地开发入口的聊天配置每次请求重新读取 `.env`。Docker 使用容器环境，修改 `.env.docker` 后需要重新运行相应启动命令以重建应用容器；仅刷新浏览器不会更新配置。密钥只在服务端使用，不返回浏览器。

## 数据库与 RAG 基础进度

统计调度迁移 008 新增三张表，数据库为 25 张表、8 次迁移，覆盖资料发布、实体与知识、MetaTFT 目录和组合统计、Riot 逐局明细、统计调度与独立参考快照。[V4 数据架构](../../docs/DATABASE_ARCHITECTURE.md) 中的 22 表审计为本次迁移前的记录，新增部分见 [统计调度](../../docs/STATISTICS_SCHEDULE.md)。知识入口为 `POST /api/knowledge/query`，存储状态为 `GET /api/storage`，Riot 采集状态为 `GET /api/riot/status`。

当前 V4 压缩包为 1,387,554 字节，包含本赛季 844 个实体、832 份文档、940 个片段。其中 678 个片段符合来源补丁 18.4 的检索资格，另外 191 个片段解释社区用语，共 869 个合格检索片段；此数不等于已构建向量数。术语单独标记 `scope: general`、`sourcePatch: null` 和编辑修订哈希，不冒用游戏补丁。统计快照仍为 204 份：2 份来源明确标注补丁，201 份按原采集时间推定为 18.4，另 1 份仍不可用。原包中 202 份统计的 `sourcePatch` 仍为 null；推定记录另存，不能把它写成来源实际返回的版本。换版日各区生效时刻和统计窗口未知，不保证推定快照的全部样本只含 18.4，也未确认 B 更新。

## V3 中文机制资料库

全站提供“白天／黑夜”显示模式并记住选择，采用暖白／炭黑两套配色。顶部常驻醒目的应用版本、赛季与机制资料补丁，版本详情独立标记游戏补丁、资源和统计版本。视觉参考、显示逻辑与核验记录见 [V3 显示模式说明](../../docs/V3_APPEARANCE.md)。

资料库新增 Little Buddy Bot 中文机制专题：8 个系统专题、19 个海克斯奖励与交互专题、8 个羁绊细则、4 个法杖细则、5 个实用参考，共 44 个专题、81 张原生表格、846 条表格记录。原图已转为中文规则和奖励分支，页面无需打开原站或查看英文截图。

海克斯奖励并入对应图鉴详情；支持中文／英文原名搜索、奖励档位切换、表内搜索、羁绊数量筛选，以及奖励中的英雄／装备跳转。另录入 248/249 个当前海克斯的精确出现阶段、模式、特殊条件和互斥关系。29 条原先含英文的海克斯效果补为来源 18.4 的中文说明；好事成双仅翻译原目录文本，未补造缺失的出现规则。

赛季特殊玩法统一收录法杖出现条件、图鉴与机制细则；默认直接显示回合、费用和限制，支持按精确回合筛选及全站搜索。战利品法球可以按真实图片辨认颜色并切换阶段，奖励行也配有图标。阵容规划器先展示已保存的个人笔记，带版本、英雄预览和文字摘要；点击「添加」再进入棋盘编辑。新笔记默认采用当前资料补丁标签，旧笔记没有版本的保留为「版本未记录」。说明见 [V3 资料库识图与个人笔记首页](../../docs/V3_LIBRARY_AND_NOTES.md)。

助手通过 `get_library_knowledge` 读取同一版本包，逐条引用来源，不把规则概率当胜率。37 个专题可用于当前来源 18.4 数值检索，其余 7 个专题因旧版本、缺少补丁或来源冲突仅展示参考。中文整理、版本核验和同步方法见 [V3_LIBRARY.md](../../docs/V3_LIBRARY.md)。

运行 `npm run sync:library` 可核验／复用当前发布包；已发布的相同版本默认跳过。同步原始采集前需保留核验锁，不会自动接受变化后的图片或英文条件。

## V2 阵容与个人笔记

- 阵容首页：当前数据库版恢复显示 10 套来源阵容，可查看队员、装备、均次、前四率、登顶率和样本；补丁显示“18.4 · 推定”，可以展开核对依据。无可用归属或补丁不同的统计仍被隔离。原包中 8 套有完整坐标，2 套未提供坐标，全部列在未摆放区，不生成替代站位。来源阶段棋盘标为示例，不补写运营步骤。
- 相关来源阵容：按共有核心和至少一半棋子关联，点击打开另一套完整来源记录。每套保留自己的统计；来源未核验为同族变阵，不能据此推出换人、换装后的胜率收益。
- 阵容规划器：从首页“编辑为个人规划”带入来源快照，或自行选择棋子、装备、星级和站位。棋盘支持选择棋子后点击格子移动、换位和移至备战席；标题、运营思路、注意事项可自行填写。个人修改不继承原阵容的实测胜率，原始来源快照可单独查看与恢复。
- 所需基础人口：普通棋子按 1 栏，远古巨龙按当前静态目录明确的“占用 2 个弈子栏位”规则计算。计算包含待摆放棋子，未计皇冠、强化或羁绊提供的额外容量；这是名单规则，不是观测到的玩家等级。规则缺失时保持未知。
- PC 阵容码：导入、导出当前标准 PC 赛季的原生名单码。码只保存英雄名单与赛季，不保存装备、站位、星级或文字笔记。解析后可先预览并导入备战席；精确匹配本地来源记录时，可另选“带入来源站位 / 装备”，这些资料由独立来源快照提供。未映射的英雄形态不猜编号。
- 个人阵容池：保存到当前浏览器，按赛季、资源及规则版本区分。旧版本笔记只读查看与导出；完整 JSON 备份包含棋子、装备、站位、星级、个人文字与来源快照。换浏览器或电脑时使用 JSON 导出／导入，原生阵容码不能代替完整笔记备份。
- 留意的海克斯与法杖：在个人规划中搜索当前目录、添加或移除关注项，随笔记保存及完整 JSON 迁移。关注项可以是多个备选，不代表已选，也不改变人口、羁绊或来源统计。法杖目录读取本地版本缓存。

旧全队工作台继续隐藏，旧入口跳转到大数据；本轮没有重新启用库存自动分配。

PC 编号映射、原生码格式、来源布局与基础人口规则的核验记录见 [RESEARCH.md](../../data/team-codes/RESEARCH.md)。

## 资料研究能力

- 图鉴：统一入口下的英雄、装备、羁绊、强化符文与合成图鉴；装备包括独立的奥恩神器分类，当前 31 件。
- 赛季特殊玩法：位于资料库内，读取当前赛季法杖／自然仙灵效果、费用、出现阶段和升级关联。S–D 采用 MetaTFT 职业选手 Spencer 的攻略评级，独立注明作者、来源与原始采集时间；升级、棱彩变体不继承基础等级。卡片可直接问 TFT助手玩法与变阵，推演建议与已观测阵容分开。
- 法杖出现条件：Little Buddy Bot 18.4 条件表与 Riot 18.4 更新说明按实际 ID 入库，当前映射 343/349 个法杖／变体。等级、金币、生命、棋盘／备战席、互斥强化、模式、精确回合窗口和再次出现冷却各自留存；出现、购买与效果触发分开。6 个缺失 ID 不继承其他形态的条件，权重和实际概率未知。详见 [WISP_CONDITIONS.md](../../docs/WISP_CONDITIONS.md)。
- 大数据：装备与棋子两个榜单，支持名称、外号、费用、装备分类和表头排序；普通装备、光明装备、奥恩神器、转职有独立图标。具备合格来源时可查看完整三件套和携带者。整体棋子 74 条、装备 126 条来自 Tactics.tools 18.4 Ranked / Diamond+，只有运行补丁匹配时才作为当前统计使用。OP.GG 搭配统计按独立归档规则标记推定补丁；段位仍未知，不借用 Tactics.tools 的口径。
- 筛选器：单个搜索框添加英雄、装备、转职和激活羁绊标签，装备可绑定持有者，多英雄时可选择查看谁的出装。MySQL 中存在当前补丁的合格 Riot 排位记录时，全部条件在同一玩家终局上查询，三栏返回实际出装、队友和完整棋子组合的统计；不足提示阈值仍展示，不放宽空结果、不与 OP.GG 合并。`POST /api/research/query/v2` 与助手的 `get_research_stats` 共用查询。尚无 Riot 合格数据时保留原来源能力边界：OP.GG 单英雄完整出装可查，任意多英雄联合统计不可用。
- 转职：原缓存保留 21 件纹章的来源持有者统计；MySQL 模式同样要求明确来源补丁或有依据的推定补丁与当前补丁匹配。旧工具的“模拟搭配”是规划示例，不能作为大数据装备或阵容结论。
- 版本知识库：网页和 Agent 读取所选后端的同一份版本资料，Docker 默认读取 MySQL，本地开发默认读取 JSON；查询不实时访问 OP.GG 或 Riot。Riot 的独立 worker 支持每日限量采集，其他来源仍由各自同步与导入命令维护。
- 云顶术语：资料库收录 191 条词条，含定义、别名、示例问答、消歧边界、适用范围和证据标签。速八、卡牌、启动等分别保留不同义项；较长词优先，避免把大天使误拆成天使。20 个英雄名称映射只附加到当前目录实际存在的实体。搜索、Agent 和统计意图共用实体别名解析；明确问题的英雄、装备及佩戴者优先于旧页面条件。术语含义使用知识卡，装备优劣仍查询统计。同名或多形态歧义不会自动选定 ID。
- TFT助手：全站悬浮入口默认收起，点击展开，可用右上角关闭、悬浮按钮或 Esc 收起；收起和页面切换保留当前会话与未发送文字，刷新后重置。可识别英雄外号与固定装备，但统计回答必须经过所选后端的版本及能力检查；数据缺失时不会生成替代装备结论。机制问题保留精确规则工具，并新增 `search_knowledge` 词法／可配置混合检索，回答引用实际资料。不采信浏览器传入的指标，不合并重叠样本；研究问答不使用旧工作台库存草案。
- 开发者模式：数据资产总览、文档与切片查看器、检索调试器、回答证据链、更新与发布记录五页。来源展示记录与 RAG 文档／切片分别计数，页面中的来源记录数不等于文档或向量数量。V4 种子包为 832 份文档、940 个片段、869 个合格检索片段，实际数据库发布与向量状态单独检查。只读查看来源、指纹、资格、发布差异和回答证据；相似度不是事实可信度。检索预览不调用聊天模型，但已配置混合检索时，未缓存查询可能调用 Embedding API。
- 异常：缺少缓存或来源字段时显示缺失，不使用演示胜率替代真实统计。

当前交付面向单用户本机研究。Riot 联合统计覆盖已采集的当前主补丁终局，样本规模和覆盖不等同成熟大数据网站。二件装、克制、星级筛选、比赛时段位和逐回合查询仍未提供；不同来源、补丁与样本不混合。个人战绩、自动游戏接入、录像识别和公开部署未实现。

开发者模式仍保留现有资料和证据查看器；新基础服务的实际状态以 `/api/storage` 为准。MySQL 与 Redis 已有适配，Milvus 连接与知识索引状态分别报告；没有 embedding 配置时不显示为已向量化。调用记录仍在本机内存按容量和时限保留，重启清空；不保存密钥、系统提示或聊天历史。数据库导入和索引目前使用 CLI，维护者发布、审核和回滚的 HTTP 管理界面尚未交付。

## 数据更新与验证

```powershell
npm run check:ai
npm run sync:data
npm run sync:knowledge
npm run sync:team-codes
npm run probe:opgg
npm run probe:patch
npm run db:dry-run
npm test
```

`check:ai` 验证真实模型列表和最小回答，不打印密钥。`sync:data` 同步并校验静态目录，同资产版本默认复用原包。`sync:knowledge` 集中录入 OP.GG、弈子与装备整体统计、羁绊、赛季机制、出现条件和 PC 编号映射，已有有效缓存时各自跳过；补齐缺项使用 `npm run sync:knowledge -- --complete`，明确重采集时使用 `--force`。也可分别运行 `sync:stats`、`sync:explorer`、`sync:traits`、`sync:mechanics`、`sync:mechanics-conditions` 和 `sync:team-codes`。后者更新当前版本 PC 英雄编号映射，不生成阵容统计或来源站位。

法杖选手评级为单独核验的本地版本文件，更新时需重新核对公开榜单；不同版本不会沿用旧评级。条件同步目前只接受已核对的 Set 18／18.4 表结构，后续补丁需调整并重新核验；未发布成功会保留旧包。`probe:opgg` 是独立联网诊断命令，网页不调用它。`probe:patch` 只读 OP.GG 默认版本与 Riot 日历，输出交叉核对结果，不写数据库、不修改历史快照，也不是每日调度器。

当前缓存状态在“大数据”页展示。OP.GG 没有提供的原始补丁、地区、段位和统计窗口保持未知；补丁推定以独立字段和依据呈现。羁绊单独显示 Tactics.tools 实际提供的补丁与样本口径，不能混用。英雄出装数据不能包装成英雄总体胜率。设计与范围见 [STATS_DESIGN.md](../../docs/STATS_DESIGN.md)，同步与失败原因见 [DATA_SOURCES.md](../../docs/DATA_SOURCES.md)，法杖规则、评级与版本覆盖见 [MECHANICS_SOURCES.md](../../docs/MECHANICS_SOURCES.md)，交付验收见 [VALIDATION.md](../../docs/VALIDATION.md)。

Overlay 竞品调研见 [OVERLAY_RESEARCH.md](../../docs/OVERLAY_RESEARCH.md)，包含 TFT Academy、MetaTFT、Little Buddy Bot 的功能及公开实现证据。游戏接入与游戏内Overlay尚未实现。

Little Buddy Bot 的知识类别、图片与结构化数据核验见 [LITTLE_BUDDY_RESEARCH.md](../../docs/LITTLE_BUDDY_RESEARCH.md)。较早的入库设想保留在 [KNOWLEDGE_INGESTION_PLAN.md](../../docs/KNOWLEDGE_INGESTION_PLAN.md)，当前架构以 [RAG_ARCHITECTURE.md](../../docs/RAG_ARCHITECTURE.md) 为准。本轮复用既有核验资料，没有重新执行全站 OCR 或自动翻译。

## 目录

`public/` 为无需构建的界面、共享棋盘与个人笔记模型；`server/` 为本机 HTTP 服务、AI 工具编排、数据适配器和原生码解析；`scripts/` 为数据同步与连通性探针；`tests/` 验证来源缓存、阵容、笔记、原生码与问答边界。

规范化目录在 `data/catalog.json`，原统计包在 `data/explorer/`、`data/stats/` 与 `data/traits/`，赛季机制在 `data/mechanics/`，PC 编号包在 `data/team-codes/`。`data/seed/current.json.gz` 和清单用于数据库首启导入；`server/storage/`、`server/knowledge/` 分别实现存储和检索。Docker 持久数据保存在命名卷。原始采集文件和种子发布包用途不同，公开发布种子前仍需核查来源许可。

个人笔记继续保存在浏览器 localStorage，不进入公共知识索引。3000 和 3001 是不同浏览器来源，笔记不会自动互通；使用规划器 JSON 导出／导入迁移。

## 数据使用范围

本版没有部署到公网。第三方接口技术可读与公开再分发许可分别验证；公开运营前仍须确认 OP.GG MCP 的展示、缓存、商用和再分发权。素材、机制与统计分别保留来源；不把 MIT 客户端许可证当作全部数据授权。

模型选择与助手内思考控制见 [模型配置说明](../../docs/MODEL_CONFIGURATION.md)。
