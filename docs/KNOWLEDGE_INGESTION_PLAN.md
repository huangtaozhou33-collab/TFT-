# Little Buddy Bot 中文机制资料与检索接入方案

日期：2026-10-08。本文是设计方案，未执行全站导入、OCR、翻译发布或 Milvus 部署。网站范围核验另见 [调研记录](LITTLE_BUDDY_RESEARCH.md)。

## 当前系统与接入目标

当前实际存储是本地版本化 JSON：`server/developer-data.mjs` 明确标记 MySQL、Milvus、Redis 未连接、embedding 未配置；`server/chat.mjs` 通过真实工具预取和实体匹配读取资料，再交给 DeepSeek 解释，没有向量召回。文档切片查看器展示结构化字段，不等同已经建立向量库。

已经接入的 Little Buddy 内容是法杖出现条件，与 Riot 更新说明分别保留出处和版本，当前映射 343/349 个目录实体。新增方案应补充缺少的奖励细节和系统规则，并复用这个资产族；先让同一条经过核验的知识同时服务资料库与助手，再增加语义检索。

## 中文资料库原型

在资料库增加“机制与奖励”，保留现有英雄、装备、羁绊、海克斯、法杖入口。机制资料分为系统概率、海克斯奖励、羁绊细则、法杖细则四组，按当前赛季、适用补丁、分类和中文名称筛选。下面只是页面结构，不是已导入内容：

```text
资料库 / 机制与奖励                 PC TFT · 当前赛季 · 适用补丁
[中文名称或别名搜索]   [系统概率] [海克斯奖励] [羁绊细则] [法杖细则]

条目列表                         中文资料卡
名称 / 类型 / 补丁                名称 · 对应当前目录实体
                                 [规则] [奖励表] [来源与差异]
                                 中文规则及触发条件
                                 条件 | 奖励组 | 内容 | 数量 | 概率及分母
                                 未知字段显示“未收录”，不会填 0
                                 [加入此阵容的留意项] [向 TFT助手提问]
                                 来源链接 / 源补丁 / 核验状态 / 更新时间
```

“留意项”是个人阵容备注，可以包含多个互斥候选，不表示局内已选，也不会参与人口、羁绊或胜率计算。新入口沿用本轮规划器中的海克斯和法杖关注功能，不恢复旧学习笔记或收藏模块。

## 采集、中文化与发布

1. 优先读取页面明确公开的 CSV、内嵌结构化表和 HTML 文字。图片仅在没有可用文字来源时成为识别输入。不要从标题、alt 或缩略图猜数值。
2. 纯图片逐张识别表头、单元格和脚注，保留图片 URL、内容指纹、区域坐标及原文。OCR 置信度只是识别质量指标，不能当作游戏事实可信度。数字、百分比、小数点、单位和条件需逐项复核；未经复核的条目只进入待审目录。
3. 名称通过当前 PC 目录的稳定 ID 对应中文显示名；英文保留作别名。遇到无法精确对应的专名，先留存英文和待映射状态，不能翻译成一个相似海克斯或跨赛季实体。
4. 中文规则用独立字段，原始英文、原始数值和来源证据仍保存。校验数量与单位、条件分支及概率口径；仅对声明互斥且穷尽的同一奖励组检查概率和。没有完整分母时不计算出现率。
5. 每页独立保留赛季和源补丁。旧补丁如 18.3 不因当前目录是 18.4 而自动升级。无补丁的内容只供历史/待核验查看；未经逐项版本核验，不进入当前数值问答。
6. 发布为带内容指纹、实体指纹、校验结果和原采集时间的不可变版本包。先生成差异预览，审查通过后切换当前清单；保留旧发布锚定哈希供回滚。网页和助手只读已发布版本，更新时离线采集一次。

来源数值冲突应同时保存两份证据：官方明确的同字段修订可覆盖当前显示，但原始第三方字段仍可查看；未解决冲突显示“来源有差异”。不把规则概率、攻略评级和对局胜率混用。批量重制图表或公开中文内容之前，先核对可使用的数据范围与再发布授权；本轮只提供结构方案和来源链接。

## 一份记录如何同时支持界面和 RAG

建议新增 `knowledge_document`、`knowledge_rule`、`reward_group`、`reward_row`、`source_revision` 和 `translation_revision` 等实体。第一批继续用现有 JSON 包格式实现，后续 MySQL 作为规范化原文、数值、修订和发布记录的权威存储；Milvus 只保存可重建的检索索引，原图/原文由资产存储保留。

| 字段 | 用途 |
|---|---|
| `documentId / entityIds / topic` | 稳定身份、当前海克斯或法杖关联、知识类别 |
| `game / set / mode` | PC TFT、赛季、标准或双人模式隔离 |
| `sourcePatch / applicablePatches / releaseId` | 源补丁与经核验适用补丁分开；锁定一个发布版本 |
| `textOriginal / textZh / aliases` | 原文、经核验中文、显示名与别名 |
| `conditions / rewardGroups / rows` | 结构化条件、奖励数值、数量、单位与概率分母 |
| `sourceUrl / sourceAssetUrl / sourceRegion` | 原页面、原图或 CSV、图片区域/表格行位置 |
| `sourceHash / normalizedHash / translationHash` | 来源、规范化记录与中文修订可独立比较 |
| `extractionMethod / reviewStatus / conflicts` | CSV、HTML 或 OCR 路径，待审/已核验，字段冲突 |
| `embeddingModel / embeddingVersion / chunkHash` | 未来索引模型和切片修订；当前均不伪造为已配置 |

切片按一条规则、一个完整奖励组或带表头的若干完整行组织，重复附上实体、版本、条件、单位与出处。不能按固定字符长度把条件与奖励、分母与百分比切开。原图用于回溯核验，进入文本检索的是核验后的中文规则与表格表达。

检索顺序建议是：锁定 PC/赛季/模式/适用补丁/发布 ID → 中文名和实体 ID 精确匹配 → 按问题读取确定性规则或奖励表 → 需要解释时再召回中文资料片段 → 输出短答案与来源。概率、数量、触发条件由结构化工具返回，避免让向量相似度决定数值事实。

将来启用 Milvus 时，可在版本硬过滤下组合关键词 BM25 和中文向量检索，再对候选做排序；这类能力有 [Milvus 官方文档](https://milvus.io/docs/search_patterns.md) 支持。中文分词、embedding 模型与重排方式需用本项目问题集评估后确定，不能以 DeepSeek 对话接口代替尚未配置的 embedding。开发者模式分别展示命中文档、切片、相关性分数、字段证据、最终送模内容；相关性不标成事实可信度。

## 建议实施顺序与验收

先扩展已有法杖规则和两三个高频海克斯的奖励表作为小批试点，另选一份系统概率表验证中文表格与版本隔离。先完成资料库和确定性查询，确认提取质量后再接 Milvus；不要以全站图片数量作为进度指标。

首批验收应包括：中文名称精确映射、同名跨赛季拒绝混用、18.3 与 18.4 不串数据、图片数字核对、条件组分母明确、源冲突可见、版本发布差异、未审核不入检索、离线读取不联网，以及助手回答能追溯到具体表格行或原图区域。个人留意项保持个人存储，不能悄悄提升为全站推荐或实测统计。
