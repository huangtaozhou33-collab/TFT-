# V3 条件出装查询

大数据默认进入「条件出装」：选择一名英雄，固定最多三件装备，也可排除装备，然后比较来源里满足条件的完整三件套。「总体与其他统计」保留原有整体榜、羁绊、阵容和持有者研究。

交互参考 [Tactics.tools Stats Explorer](https://tactics.tools/explorer?f1=u_18_0&f2=i_DA_Artifact_Dawncore_18_0&rg=1) 的先设置条件、再研究结果的方式。当前条件三件套仍使用本地 OP.GG MCP 已收录出装数据；没有接入 Tactics.tools 逐对局接口，也不继承其 Diamond+、18.4 或地区口径。

## 查询行为

- 固定装备属于完整三件套，不在普通三件套外加第四件。
- 仅比较同一英雄的实际完整三件记录。排除散件、未知 ID、超过三槽、唯一装备重复和无效统计；重复排列保留一条来源记录，样本不相加。
- 默认最低样本 100，按平均名次从低到高；可切换前四率、登顶率和样本数，也可用表头反转排序。
- 不满足门槛时返回没有合格候选，不自动降低门槛。没有匹配组合时不拼接单件适配榜或普通出装。
- 查询条件可保存到 URL，包含英雄、固定/排除装备、样本门槛和排序；不包含聊天或结果指标。
- 每行统计属于英雄携带该完整三件套的来源样本，不代表装备的因果收益、全局理论最优或任意阵容联合胜率。

## 页面和 Agent 共用

`public/build-query.js` 负责校验、固定装备计数、筛选及确定性排序。`server/conditional-builds.mjs` 读取现有英雄出装缓存。页面通过 `POST /api/builds/query` 查询，Agent 的 `get_conditional_builds` 调用同一服务。

`server/build-intent.mjs` 识别中文/英文装备名称和常见外号，例如「小法带上黎明核心之后最佳三件套是什么」。页面问答沿用核验后的条件、排序和最低样本；明确指定另一英雄时不套用旧英雄条件。客户端传入的指标和选中行仍须在本地来源中重新核验。

明确的条件出装查询直接生成统计回复，返回 `answerMode=conditional_statistics`，不请求语言模型。解释机制、阵容分析和复杂比较继续使用已有模型流程与工具证据。不存在的固定组合直接报告缺口，不降级为无关阵容示例。
